# Prototype build report

The lead builder's report on the consolidated prototype (before the verifier rounds). `<unified>` is the scratch directory of the prototype (not part of the repository); the code is in `../../prototype/patches/`.

## Summary

Built the consolidated prototype in <unified>/repo on branch `proto`, in 5 commits on top of pristine df934a7. It contains (a) D's descriptor/decoder/exporter/input trimmed to §3, with the 10-name `invoice-data` facade; (b) `invoice(data: auto, custom: none)` with re-entry by role over every key, taken from the descriptor's `invoice-params`, plus the R7 panics, sealed `hydration`/`custom` and the data issues appended after check-data; (c) C's rows engine behind an implicit `_items-slot` in line-items.typ and C's closure-held `invoice-data.items` marker, with marker assertions and lazy coverage issues; (d) B's `payment(..)` with A's paid-by-transfer account; (e) region `vat-rates`; (f) unsealed custom fields and the party `custom` key; (g) a result module that does not load the descriptor. A pristine clone sits next to it. The examples, data, generators, fuzz corpus, fixtures, benchmarks and per-proof scripts are under proto/, and one script (proto/selfcheck.sh) runs every proof P1–P10 on 0.15.1 and 0.14.2.

Final run (run 3): every proof passes on both compilers except two performance budgets.

- P1: 36/36 matrix and 26/26 edge cases are md5-identical to the hand-written version on pristine 0.6.0, embedded XML included; so is the §3.10 example (file and inline).
- P2: the 60 integration tests, the template md5 and metadata count, and all 313 test documents are unchanged.
- P3, P6, P7, P8 and P10: all pass.
- P4: 0 hard aborts in 69 faults.
- P5: 72/72 of the new fixtures and 51/51 of D's fixtures agree; codegen works with all three tools.

Performance:

- The hydrated 300-row basic e-invoice runs at 0.57× (0.15.1) and 0.58× (0.14.2) of the hand-written one, within the 0.6× gate. Before a decoder speed pass it was 0.61×/0.60×; with C's separate format-item change (S7a, side branch `proto-s7a`) it is 0.55×/0.56×.
- The decoder costs about 0.42 ms per basic row (right at the 0.4 budget) and 0.49–0.52 ms per tree row (over budget).
- The root import grows by about 1.4–1.6 ms traced. Only the facade alone (0.05–0.07 ms) stays under the 0.2 ms budget.

Everything new is lazy: no benchmark invoice without data loads `src/contract/*`.

## Deviations from the synthesis

- 'Direct child of line-items' interpreted as: no group/bundle between line-items and the marker; an apply(..) around it is transparent (needed for the 'apply around the slot' P1 fixture; checked via the loom path in the marker's measure).
- 'At most one marker' asserted per line-items by the implicit slot (counts a marker frame of its own kind, which it always removes); with root's existing 'one line-items' assertion that is one per invoice; root's measure does not see markers.
- Item-level modifiers have no `tax` (new descriptor object `item-modifier`): item.typ panics when an item's modifier pins another VAT category.
- Extra decoder-only rules for crash-freedom: <= 28 significant digits per decimal (the spec pattern admits 30, which decimal() rejects), |price x quantity / base| < 1e18, base-quantity >= 0.0001 after rounding, note/origin dropped on bundle items, bundle without valid item dropped, null array element is an issue; not expressible in JSON Schema (decoder-only fixtures).
- Percent pattern aligned to the spec (^[0-9]{1,3}(\.[0-9]{1,6})?%$) in decoder and schema (D used a wider one).
- Tax objects built as tax.new(rate, category, label of the constructor, grounds, code) (C's mapping, equal to the tax.\* dictionaries); '19%' stays a ratio resolved by infer-tax (D converted to tax.vat).
- Region pass runs in hydrate() with the locale's region (and in decode/check with region:) and leaves out the offending tax value, not the row.
- Added: small business vs tax across layers (data small-biz true drops the skeleton tax; data tax under skeleton small-biz is issue schema/tax) and an object rule `excludes-if-true` for tax + tax-exempt-small-biz: true in the data.
- Signature-test classes are design|document|issuer|data|body (`invoice-params` in schema.typ); `custom` is classified document rather than a class of its own.
- vat-rates needed a base entry (normalize.vat-rates: none in region/base.typ) because the locale factory rejects undeclared region keys; infer-tax not rewritten on the list, a unit test pins that every listed rate resolves.
- The implicit slot lives in line-items.typ (imports contract/rows.typ only when hydrated); coverage issues moved from root.typ to contract/hydrate.typ (root calls them only when hydrated) after tests/theme/report-lang failed on an issue key without locale texts.
- Result: record builder in contract/result.typ (no descriptor), shape in contract/result-schema.typ (loaded only by schema(kind: result)); D's --input invoice-pro-result=attach dropped (Q6); package version read from ../../typst.toml instead of /typst.toml; root reads --input invoice-pro-result from sys.inputs directly (not injectable).
- load() without a data input returns none without loading contract modules; decode() never consults sys.inputs (a decode() record plus a CLI input panics as two sources).
- The repo has 60 integration tests (53 PDFs + 7 expected panics), not 53; template md5 compared pristine vs prototype under one layout (881821b7318c / 8a1c8b464422), not the synthesis' ba5d9a49b5de / c7e98da669bc, which came from another file location.
- Edge twins and the fuzz skeleton got payment terms appended so zf=auto produces a valid e-invoice (IP-PAY-06 also stopped pristine).
- Conformance fixtures regenerated for the trimmed format (72): D's extension-based cases (Q7) dropped/now valid; D's literal 51 fixtures checked for schema/decoder agreement only.
- Decoder hot path added (plain values decoded inline, required keys and union kinds precomputed in the descriptor): reports byte-identical before/after on 72 fixtures and 69 corpus documents.
- L18 perf gate: only LAZY_MODULES extended in tools/perf/gate.py; the hydrated-300 gate is proto/bench/p9.py.
- L16 (localized schema-\* texts, 'Daten / Data' chip) not implemented.
- Generated/copied fixtures (proto/eq/hand/\*, the engine judge's edge-hand.typ, e2-hand.typ, common.typ, e2-common.typ) left unformatted; all repo .typ changes are typstyle-clean.

## Known gaps

- P9 decoder budget: about 0.42 ms per basic row is right at the 0.4 budget; about 0.5 ms per tree row is over it. The synthesis' mitigation (a row path specialised from the descriptor) is not built.
- P9 root import: only the facade meets 0.2 ms. The eagerly loaded payment.typ and the longer invoice.typ/line-items.typ add about 1.4–1.6 ms traced (parse cost). Untraced timing cannot resolve this (+2–5 ms within VM noise).
- The 300-row ratio gate passes for kind b (0.57×/0.58×, before the decoder pass 0.61×/0.60×); tree invoices stay at 0.68–0.70× (0.64–0.68× with S7a). The remaining gap is unchanged layout code (the table part dominates).
- A document-level absolute modifier without `tax` over two or more VAT categories whose items add up to exactly 0 still stops the compile (modifier-applicator). The decoder cannot see totals, and the case is not in the corpus.
- Wrong identifier check digits (leitweg, gln, …) are e-invoice rule errors (IP-ID-01): with zugferd-errors 'panic' they stop the compile instead of becoming a data issue.
- L16 not implemented: there are no localized texts for the schema-\* issues, so the messages are English and the report shows no 'Daten' chip.
- Not part of the prototype: L26 docs, the S7a–S7d speed PRs (S7a only measured on a side branch), the S8 bug fixes, and CI wiring for codegen, conformance and the schema drift check (they exist as scripts).
- Decimal digit limits, the amount range, nesting depth, the modifier VAT scope and region VAT rates are checked only by the decoder; the JSON Schema cannot express them.
- No external Factur-X/XRechnung validator was run: CII-SR-467/470 rest on invoice-pro's own rules engine (zugferd-errors 'panic') plus XML inspection.
- tytanic is not available: test files are compiled directly and their assertions panic on failure. The stdin case under --root <unified> relies on a symlink <unified>/dev/stdin -> /dev/stdin.
