# The prototype's harness

The builder's test harness of the [data API prototype](../README.md): the generators, comparators, corpora and scripts behind the proofs P1–P10 ([concept §11.2](../../README.md#112-the-ten-proofs)). Only the sources are here. Outputs, logs and the generated invoices (`eq/data/`, `eq/hand/`) are left out, and so are the verifiers' own scripts and corpora (below).

This folder is a record, not a test suite of the package. No CI job runs it. Stages S1, S3 and S5 of the [implementation plan](../../README.md#12-implementation-plan) port the parts that become CI gates into `tools/` and `tests/`. Until then, this is the only copy that survives the exploration's scratch directory.

## Layout and use

The scripts address the Typst root `<work>` of [`run.sh`](../run.sh): `<work>/repo` (0.6.0 + the patches), `<work>/pristine` (0.6.0) and `<work>/proto/{examples,data}`. Copy this folder into `<work>/proto/` after `run.sh` has built the work directory:

```sh
docs/concepts/data-api/prototype/run.sh ../data-api-proof
cp -r docs/concepts/data-api/prototype/harness/* ../data-api-proof/proto/
cd ../data-api-proof/proto
python3 -I gen/gen.py 5,50,300 b,r,t           # writes eq/data/*.json and eq/hand/*.typ
eq/eq.sh typst "b r t" "5 50 300" "none auto"  # P1: pristine == hand-written == hydrated
```

The files of `examples/` here join those of `prototype/examples/` (the extra skeletons that P6, P7 and P8 compile).

Changes against the exploration's copy: `schema/codegen.sh` reads the directory of the code generators from `CODEGEN_TOOLS`, `selfcheck.sh` takes the compilers from the environment and the layout from its own location, and the header comment of `examples/skeleton-no-bank.typ` names the concept instead of the synthesis.

Changes for the maintainer's decisions of 2026-11-03 (patches 0011–0014, and 0015 for the verifier's findings on them):

- **Names (Q19).** Every skeleton and script uses the namespace `data` (was `invoice-data`).
- **Fail safe (Q1).** A hydrated invoice is strict by default (`validation: auto`). `misuse/p3.sh`, `payment/p6.sh` and `result/p8.sh` pass `--input invoice-pro-validation=draft` where they expect a draft or read the result of bad data, and check that the default stops with the problems and the debug hint. `misuse/p3.sh` also checks the flag `none` (checks off), an explicit `validation: "draft"` in a skeleton (`misuse/explicit-draft.typ`, new) and the draft of an invoice without data. `fuzz/fuzz.py` takes a mode, `default` or `draft`; `selfcheck.sh` runs both. For patch 0015, `misuse/p3.sh` also checks the flag `auto` (no override), the findings of the layout in the stop (`misuse/layout.typ`, new: footer fit, identity, scope contrast, an empty totals part; the stop counts as many problems as the draft) and a binding named `data` made before and after `import *` (`misuse/shadow-before.typ`, `misuse/shadow-after.typ`, new).
- **Import budget (Q2).** `bench/impcount.py` is new; `selfcheck.sh` runs it before `imptrace.py`. For patch 0015, `bench/imptrace-names.py` is new (`selfcheck.sh` runs it last): the tree's name alone moves the traced and the untraced import (the same code under `/prst` instead of `/pristine` reads 1.5 to 3.7 ms apart traced and up to 9 ms untraced), and even over 10 equal-length names its A/A pair differs by up to 0.9 ms, so neither timing resolves the 1 ms budget; the instruction count decides it.
- **Signature (P10).** `signature/p10.sh` has two more mutations: an issuer parameter that `invoice()` does not pass to `hydrate(..)`, and a document key that becomes an issuer key.
- `selfcheck.sh` runs typstyle on the changed files that still exist (`--diff-filter=d`: patch 0011 renames a file).
- After the critique of the concept's third draft, the P4 step of `selfcheck.sh` also runs `fuzz.py` on 0.14.2 with an e-invoice, so it covers all 8 runs of the fault corpus.

## What is not here

- Outputs and logs (`out/`), the generated invoices (`eq/data/`, `eq/hand/`: run `gen/gen.py`) and the generated types (`schema/out/`: run `codegen.sh`).
- The verifiers' scripts and corpora: the robustness corpora r1, v3 and v4, the 3154 schema-walk mutations, the 2201-document compile sweep, the 171 targeted probes and the P10 mutations. They stay in `<session>/exp/unified/verify-*/` with several hundred MB of outputs. [`verification.md`](../../process/review/verification.md) records their commands, case lists and results; S1 rebuilds the corpus that becomes a CI gate from the fault corpus here and those case lists.
- Requirements: bash 4 or later, GNU coreutils (`md5sum`), Python 3 with `jsonschema` (P5), `pdfdetach` (poppler; P1, P3, P6), `valgrind` (instruction counts) and, for `codegen.sh`, the three code generators.
