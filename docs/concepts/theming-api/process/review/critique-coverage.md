# Critique of concept draft 1, lens: REQUIREMENTS COVERAGE (key: coverage)

Object under review: `scratchpad/concept/draft-1.md` (1125 lines, read in full).
Sources traced: `research/business-requirements.md` (R1-R44, P1-P8, tensions §11), `research/docs-tests-intent.md`
(issues, promises, open questions), `research/_digest.md` (open questions of all 7 reports), the four proposals
and `designs/_panel-digest.md` (judge MUST-ADDs).
Experiments: my copy `scratchpad/crit-coverage/` (typst 0.15.1). New probes in `tests/crit/c1..c5*.typ`, outputs
`out/crit-*.png`. Evidence tags: VERIFIED (reproduced), SOURCE (read in code/docs), REASONED.

---

## 1. Headline

The draft covers the _architecture_ of nearly every MUST, but the coverage claims in its tables are stronger than
what the concept specifies or the prototype does. Five gaps are serious:

1. **Identity guard is hollow and incomplete (VERIFIED).** It checks that `title`/`recipient` are _hosted and
   non-empty_, not that invoice number, date, supplier name/address and tax ID appear. `part("title", ..) => [Dear
customer]` compiles into an invoice with no number and no date (c1). Removing letterhead/footer/info/references
   compiles into an invoice with no supplier address and no tax number (c2). `theme.plain` (the preset!) ships with
   no sender at all (`out/m-plain-plain-1.png`). The maintainer judge's MUST-ADD "layout must host recipient **and
   sender**" was dropped silently, though the draft's graft list claims it.
2. **R4 tabular figures / numeric font and R12 stylable marks are declared but dead (SOURCE).** `fonts.numeric`,
   `fonts.figures` and `colors.mark` have no consumer anywhere in `src/theming` or the table renderer; marks take
   `0.25pt + black` from the layout literal. §10 "Not verified" does not mention it.
3. **#18 / footer-dynamic regression (VERIFIED).** `info.*` motifs inside region content render empty with no
   error (c3: footer prints "Owner: / IBAN"). v0.4.1 sold this as a feature and `tests/integration/footer-dynamic`
   tests it. The draft neither keeps nor retires it.
4. **R44 migration (SHOULD) is absent.** No mapping table for `themes.DIN-5008(form, font, hole-mark,
folding-marks, color-row-*, margin, footer)` / `themes.blank` / `.with(document:)` (11 tests) /
   `.with(line-items:)` (6 tests), nor for the dropped blank promise "native `set page` before `invoice` works".
5. **Persona walkthroughs over-claim.** P3 gets a placeholder slip, not a QR-bill, with no data path; P8 uses
   `locale.en-us`, which does not exist; P6 reads `ctx.locale`, an _internal_ key per §5.2; P2's pdf mode shows the
   continuation header printed over the page-2 letterhead art (verified in `out/sheet-p2.png`), and the walkthrough
   code omits the fix the draft itself recommends.

## 6. Findings (ranked)

### COV-1 (blocker) Identity guard does not guarantee invoice number, date, supplier or tax ID. VERIFIED

- Where: §5.3 rows "invoice identity", "recipient"; §3.6 Required column; `validate.typ:8-10`, `frame.typ:57-68`.
- Evidence: `tests/crit/c1-title.typ` (title replaced by `[Dear customer]`) compiles; `out/crit-c1-title-1.png` has no invoice number and no date. `tests/crit/c2-nosender.typ` (letterhead/footer/info/references removed, address hosts only recipient) compiles; `out/crit-c2-nosender-1.png` has no supplier address and no tax number. `theme.plain` itself renders no sender (`out/m-plain-plain-1.png`). Maintainer judge MUST-ADD ("recipient and sender"), business judge ADD (a) ("number, date, title, recipient ... or fall back to core output") and #26/#34 are not met, though §"Grafts" credits both judges.
- Fix: make identity _data_, not placement: core renders a minimal identity line (number, date, supplier name + address, VAT ID/tax no.) whenever the resolved frame did not emit them, or, cheaper, add `sender` (exactly once, first page or flow, not counted when `stationery != "generated"` since the paper carries it) and a `tax-id` role to `required-roles`, and give `title`/`sender` renderers a view-level assertion (the frame checks that `view.document.number` text occurs by wrapping it in a labelled element and `query`ing it). Add `sender` to `plain`.

### COV-2 (major) R4 and R12 promises are dead tokens. SOURCE

- Where: §3.2 rows `fonts.numeric`, `fonts.figures`, `colors.mark`; decision table "Tokens ... R3/R4".
- Evidence: no consumer in `src/theming/**` or `src/themes/components/**` (grep); marks stroke from `layouts.typ:24,63` literals; `items-table`/`totals` (`parts/body.typ:25-80`) never set `number-width` or `font`.
- Fix: wire them (amount cells `text(font: fonts.numeric, number-width: figures)`, `marks.stroke: t => t.strokes.hairline + t.colors.mark` as the layout default), add them to §10 "not verified", and add a coverage test asserting every token path is read by at least one built-in part.

### COV-3 (major) #18 / footer-dynamic: `info.*` motifs in region content silently vanish. VERIFIED

- Where: §3.4 `parts: content`, §6 "legal footer ... hosts block parts, content and functions".
- Evidence: `tests/crit/c3-motif.typ`: footer content `[Owner: #info.sender.name / IBAN #info.iban]` renders "Owner: / IBAN" (`out/crit-c3-motif-1.png`); no error.
- Fix: weave content cells with `eval-content(ctx, ..)` in `render-cell` (the research proved it works in page furniture, component-contract E10) or panic when a content cell contains invoice-pro motifs, and document that functions `(ctx, view) => ..` are the replacement.

### COV-4 (major) R44 migration mapping and test-migration plan missing. REASONED/SOURCE

- Where: whole draft (no migration section); Appendix.
- Evidence: business-req R44; docs-intent §2.1-2.4 (README/template call, 35 blank sites, `document` hook ×11, `line-items` hook ×6, `color-row-*` from PR #36, blank's `set page` promise).
